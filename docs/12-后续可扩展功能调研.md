# 12 - 便签应用功能调研与后续扩展建议

**调研日期：** 2026-10-12

**适用项目：** StickyNote Windows 桌面便签
**定位：** 为后续产品规划提供候选功能与优先级，不构成版本承诺。

**实现进展：** P0 与 P1 已在 v1.8.0 实现或完成可行性评估；详见 [v1.8.0 开发说明](./13-v1.8.0-开发说明.md)。后续候选请看 [现有功能优化与扩展清单](./14-现有功能优化与后续扩展清单.md)。

## 1. 调研范围与原则

本次对照 Microsoft Sticky Notes、Google Keep、Apple Notes 与 OneNote 的官方帮助文档，重点观察便签创建、组织、检索、提醒、内容表达和离线使用体验。项目当前能力依据仓库中的 `features/` 模块及 `docs/03-功能需求说明书.md`、`docs/09-优化计划.md` 进行去重。

遵循两个产品约束：

- **不纳入商业化功能**：不提出订阅、付费墙、广告、付费云空间或面向营收的功能。
- **联网不得成为必需条件**：核心编辑、保存、搜索、提醒、备份和导入导出应在本机完成。同步等联网能力保持可选；断网时本地数据仍可读写。

官方资料显示，Microsoft Sticky Notes 强调快速创建、搜索、图片、颜色和跨设备同步；Google Keep 提供颜色、标签、置顶、归档、清单、绘图和提醒；Apple Notes 提供标签、标签浏览器与按条件筛选的智能文件夹；OneNote 支持按标签汇总并搜索笔记。这些模式可用于发现方向，但不意味着 StickyNote 需要照搬完整产品形态。

## 2. 对标功能与项目现状

| 能力方向 | 市面产品做法 | StickyNote 当前基础 | 可扩展空间 |

## 3. 候选功能清单

以下按用户价值、离线适配度和对现有架构的复用程度排序。P0 表示优先评估，P1 表示可在核心体验完善后评估，P2 表示探索性方向；它们不是发布时间表。

### P0：优先评估

#### 3.1 搜索体验完善

- 在结果中高亮标题和正文命中词，并显示更具上下文的摘要。
- 提供本地筛选项：标签、创建/修改时间、是否有提醒、是否含图片/附件、置顶/归档状态。
- 支持清除条件、空结果提示及键盘浏览；可考虑保存常用筛选条件为“智能视图”。
- 搜索完全使用本地索引或本地文件，不依赖在线服务。

**依据：** 现有搜索和标签过滤可复用；Apple 智能文件夹与 OneNote 标签结果展示了筛选和回顾的成熟交互。

#### 3.2 归档、回收站与恢复

- 将“暂时收起”和“永久删除”分开：归档便签仍能搜索、查看和取消归档。
- 删除先进入本地回收站，提供恢复、永久删除和保留期限设置。
- 批量归档、恢复和删除与现有批量操作保持一致，并为锁定便签定义明确行为。

**价值：** 降低误删风险，帮助用户清理桌面，同时保留历史记录。数据操作应本地完成。

#### 3.3 清单与轻量任务流

- 支持在便签正文中插入复选框清单，勾选状态自动保存。
- 支持未完成项优先展示、完成项折叠，以及将已完成事项重新打开。
- 提供“仅看未完成”本地筛选；不引入账户、在线协作或任务服务依赖。

**依据：** Google Keep 把清单作为常用笔记类型；Apple 智能文件夹也可按清单状态筛选。

#### 3.4 本地数据可恢复性

- 备份恢复前展示内容摘要、时间、便签数量和校验结果。
- 支持恢复前自动创建当前状态备份，并在恢复失败时保留原数据。
- 增加本地历史版本/误编辑恢复的可行性评估；明确版本数量、磁盘上限及清理策略。
- 导入时提供预览、重复项处理方式和部分失败报告。

**依据：** 项目已有备份与导入导出能力，优先提升可信度和可预期性，避免只增加新的数据格式。

### P1：体验增强

#### 3.5 本地智能视图与组织

- 以标签、颜色、置顶、提醒状态、创建/修改时间和内容类型组合筛选。
- 支持用户命名和调整条件，并在便签列表中作为快捷入口。
- 智能视图只保存查询条件，不复制或移动便签；删除视图不影响便签本身。
- 对大写/小写、中文字符和空标签等条件定义一致的匹配行为。

#### 3.6 快速捕捉与批量处理

- 提供更轻量的新便签输入入口，以及可选择启用的剪贴板文本捕捉。
- 支持把选中文本快速转换为新便签；对剪贴板访问给出明确的用户触发点。
- 便签列表支持多选、批量加标签、改颜色、置顶、归档和导出。
- 所有捕捉仅在本机处理，不自动上传剪贴板或便签内容。

#### 3.7 附件和图片管理

- 评估拖放图片、粘贴图片、附件列表与便签预览的统一体验。
- 明确附件在备份、导出、删除和恢复时的生命周期与路径规则。
- 附件保存在项目的数据目录；断网可查看本机附件。外链可作为普通链接保存，不作为附件可用性的前提。
- 后续可评估本地 OCR 搜索，但需先衡量安装包体积、语言覆盖、性能和隐私提示。

#### 3.8 提醒中心与可靠性

- 统一查看未触发、已到期、已完成的提醒，支持稍后提醒和完成处理。
- 应用未运行期间到期的提醒，在下次启动时提供清晰的补处理入口。
- 对重复提醒的时区、夏令时、重启恢复、重复触发和删除便签后的状态制定规则。
- 提醒调度与显示使用 Windows 本机能力，不依赖服务器。

#### 3.9 界面与无障碍打磨

- 提供紧凑列表/卡片视图、排序偏好和更明确的键盘焦点状态。
- 完善高对比度、缩放/DPI、键盘操作、屏幕阅读器名称和主题对比度。
- 允许用户保存桌面布局/窗口排列方案；布局保存到本机，适应屏幕数量变化。

### P2：探索方向

#### 3.10 版本历史与差异恢复

便签内容可按时间保留若干本地历史快照，支持预览并恢复指定版本。需要设计存储上限、锁定内容处理和加密兼容；不应无提示地无限增长。

#### 3.11 本地全文检索扩展

若未来数据量或附件类型增加，可评估可重建的本地索引、附件文本提取和可选 OCR。索引损坏时应能从本地原始数据重建，且核心编辑不依赖索引在线服务。

#### 3.12 可选互操作增强

在现有 TXT/Markdown/ZIP 等能力上，评估更完整的 Markdown 文件夹导出、标准 JSON 清单和从常见格式迁移的映射说明。导出应保留标题、正文、标签、提醒等可表示字段，并清楚说明不能无损表达的内容。

## 4. 建议的推进顺序

1. 先核查现有代码与 UI，关闭需求文档和实际行为之间的差异；尤其确认搜索、提醒、批量操作、备份恢复和附件的已实现边界。
2. 以“搜索体验完善、归档/回收站、清单编辑、备份恢复预览”作为第一轮候选，分别补充用户场景、数据模型影响和验收条件。
3. 第二轮评估智能视图、快速捕捉、提醒中心与附件管理；尽可能复用现有标签、搜索、提醒、导入导出和图片模块。
4. 版本历史、OCR 和索引升级等方向先做存储与性能验证，再决定是否立项。
5. 每项功能均保留离线验收场景：断网启动、编辑保存、搜索、提醒恢复、备份/恢复、导入/导出；任何同步功能都作为明确开启的可选项。

## 5. 不纳入本清单的方向

- 订阅、广告、付费升级、付费云存储、交易或其他商业化机制。
- 将登录、网络连接或云端服务作为新建、编辑、读取、搜索、提醒或备份的前置条件。
- 自动把便签、剪贴板或附件上传到第三方服务的 AI 摘要、在线识图或在线搜索。

这并不排斥用户主动配置的可选同步；同步不可用时，用户仍应能继续使用本地数据。
