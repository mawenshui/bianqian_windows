# StickyNote 现有功能优化与后续扩展清单

**调研基线：** v1.9.0。**调研日期：** 2026-10-16。**状态更新：** P0-1～P0-3、P1-1～P1-3 已纳入 v1.10.0；第五节仍为后续候选。下文的 v1.9.0 缺口和建议保留调研时语境，不描述当前版本缺失。

## 调研范围与判断方法

- 优先看个人作者、小型团队及有明确使用场景的小众桌面笔记产品，不按下载量或市场份额排名。样本覆盖 Windows 桌面便签、跨平台本地笔记和桌面 Wiki。
- “产品做法”来自产品官网、官方帮助或项目仓库 README；“解决的痛点”和“对 StickyNote 的启发”是依据功能设计作出的推断，不代表访谈、使用量或实测结论。仓库 README 只能证明项目方如此描述，不能证明每种环境下均可靠。
- 所有建议以核心能力可离线运行为前提。新建、编辑、搜索、提醒、备份、恢复、导入和导出不能依赖账号或联网；同步与更新检查保持可选。
- 优先处理“写得快、找得到、不会丢、需要时出现、不需要时不挡事”。不把桌面便签扩展成完整的知识库或项目管理系统。

## 一、v1.9.0 已完成的现有功能优化

以下八项保留原实施顺序，用于区分现状与新建议。实施与验证细节见 [v1.9.0 开发与发布验证](./16-v1.9.0-开发与发布验证.md)。

| 顺序 | 已交付能力 |
| --- | --- |
| 1 | 备份恢复差异预览、附件统计、失败定位和恢复前安全备份。 |
| 2 | 回收站清理影响预览、孤立附件检查与归档。 |
| 3 | 搜索筛选反馈、结果数、归档范围及可重建的增量记录缓存。 |
| 4 | 提醒启动补检、时间跳变处理和最近操作撤销。 |
| 5 | 清单独立撤销/重做及含清单状态的预览、文本导出。 |
| 6 | 手动快速记录、按需读取剪贴板及批量操作结果反馈。 |
| 7 | 跨屏布局恢复、高对比度与关键控件的无障碍名称。 |
| 8 | MSI、便携版及迁移、数据保留的发布验证清单。 |

## 二、个人开发者与小众产品：做法及其针对的痛点

| 样本与一手资料 | 产品实际做法 | 它针对的痛点（推断） | 对 StickyNote 的启发 |
| --- | --- | --- | --- |
| [Stickies（Zhorn Software）](https://zhornsoftware.co.uk/stickies/) | 作者明确说是为减少贴在显示器上的纸条而写；便签可按时间重新出现，也可附着于应用、网站、文档或文件夹，仅在对应对象出现时显示。 | 长驻便签越多越遮挡桌面；某条便签只有在处理对应工作时才有价值。 | 从“始终显示”延伸到用户主动设置的场景唤回，但必须能清楚解释何时显示、随时解除关联。 |
| [Sticky-Note（ikohnt，GitHub 项目）](https://github.com/ikohnt/Sticky-Note) | 提供全局快捷键捕捉、便签堆叠、设备本地相似便签提示、原子写入与损坏数据旁路保留；项目说明不需要账号或云端。 | 想法来得快，便签多了又难整理；崩溃或文件损坏不应让所有内容消失。 | 快速入口已具备，应评估便签收拢与重复内容提示；数据安全优先于花哨的自动整理。 |
| [StickyPad（BaeTab，GitHub 项目）](https://github.com/BaeTab/stickypad_windows) | 托盘加全局快捷键新建；快速切换器跳转便签；统一查看各便签清单；可选把便签放在用户指定的 Markdown 文件夹，另有 JSON 备份和多种导出。 | 记录入口虽快，日后仍可能找不到；任务散在多张便签；用户希望内容可由其他工具读取。 | 把“直达已有便签”和“清单聚合”做成现有数据的视图；先做可往返的导出包，再评估直接以文件夹作为实时存储。 |
| [Ghost Notes（navyabijoy，GitHub 项目）](https://github.com/navyabijoy/invisible-notes) | 使用系统窗口保护机制让便签在屏幕共享或录制中不可见，并提供工作区、缩成小圆点和本地存储；项目同时列明 Windows 版本等限制。 | 会议或录屏时，私人提示需要留在自己眼前，却不应进入共享画面；暂时不看的便签不该挡操作。 | 先评估一键收起或演示模式；若以后做录屏排除，必须逐环境实测并明确局限，不能把它当作保密保证。 |
| [QOwnNotes（官方概述）](https://www.qownnotes.org/getting-started/overview.html) | 笔记是普通文本/Markdown 文件，可直接使用已有文件；连接 Nextcloud/ownCloud 是可选能力。 | 不想被某个应用的数据格式锁住，也不想为了本机写笔记先配置服务。 | 设计有版本号的开放导出格式、可复原导入和清楚的无损范围；不把联网同步放到基础路径。 |
| [Zim Desktop Wiki（官方手册）](https://zim-wiki.org/manual/About.html) | 页面是本地文本文件，支持页面间链接、反向链接和层级导航；附件仍是普通文件。 | 笔记积累后，仅按标题或标签找内容难以看出关联。 | 可试验轻量便签互链，但仅在检索和迁移基础稳定后考虑；无需照搬完整 Wiki 结构。 |

这些样本提供的是设计线索，不是 StickyNote 应逐项复制的功能列表。尤其是自动聚类、录屏排除和实时文件夹存储，会引入误判、平台差异或数据冲突，需要独立验证。

## 三、对照 StickyNote v1.9.0 的具体缺口

| 用户路径 | 当前已有 | 值得进一步解决的问题 |
| --- | --- | --- |
| 随手记录 | 全局 `Ctrl+Shift+N` 新建、托盘快速记录、用户触发的剪贴板记录。 | 记录后如何低成本回到那张便签；频繁新建是否造成桌面拥挤。 |
| 找回内容 | 标题和正文搜索、筛选、智能视图、结果高亮与可重建缓存。 | 大量便签时能否用键盘直接跳转；清单任务分散时能否统一查看。 |
| 避免丢失 | 自动备份、恢复预览、安全备份、回收站与附件保护。 | 单张便签误改后的细粒度回退；跨机器迁移时对富文本、提醒、附件和清单能否完整复原。 |
| 控制呈现 | 置顶、归档、贴边、布局预设和跨屏恢复。 | 某项工作暂时结束后如何收起相关便签，回到该工作时如何重新出现。 |
| 本地数据控制 | 离线核心操作、JSON 批量导出附带附件、TXT/Markdown 文本导出、可选同步。 | 导出是否有明确格式版本、校验和可预览的反向导入；包含敏感内容时如何避免意外明文泄露。 |

现有全局新建、搜索、清单、布局、备份和导出已经解决了部分问题。下面的优先级只针对尚未交付的增量，不能把它们写成“已有功能”。

## 四、现有功能优化建议（下一轮候选）

按数据安全、日常使用频率和与现有模型的贴合度排序。每项先做小规模原型或数据验证，再决定是否进入版本计划。

| 优先级 | 建议 | 最小可交付范围与完成判据 | 依据及主要风险 |
| --- | --- | --- | --- |
| P0-1 | 单张便签本地版本历史 | 仅在内容实际变化时保留有限快照；可预览差异并恢复，恢复动作本身可回退；展示占用并允许清理。主密码目前只做启动验证，历史的磁盘保护须单独设计，不能声称已沿用便签加密。 | 备份解决整库恢复，不能方便地撤销数日前的一张便签误改。需验证富文本、附件引用、清单与历史保留上限。 |
| P0-2 | 可往返的本地迁移包 | 在现有导出上增加格式版本、manifest、附件校验和导入预览；用同一版本安装包完成“导出→新空库导入→逐项核对”。Markdown 可作为可读副本，完整恢复以结构化数据为准。 | 借鉴 QOwnNotes/StickyPad 的数据可携带性。难点是富文本、提醒状态、附件、加密信息及旧版兼容；导出明文必须显著告知。 |
| P0-3 | 键盘快速切换已有便签 | 一个快捷入口搜索并定位便签，显示标题、片段和标签；回车聚焦，支持未打开和归档项，清楚标记回收站不参与；与现有搜索共用本地数据。 | 借鉴 StickyPad 的快速切换器。避免重复建设另一套索引与排序规则，量化打开到聚焦的步骤和耗时。 |
| P1-1 | 清单聚合视图 | 将现有各便签清单条目汇总，能按完成状态筛选并跳回原便签；勾选结果写回原条目，不另建任务数据库。 | 借鉴 StickyPad 的统一待办视图。需保证与便签内撤销/重做、归档和删除状态一致。 |
| P1-2 | 贴边收起状态管理 | 保留现有拖到窗口边缘、标签悬停预览和点击固定展开；补充贴边状态保存、托盘查找及展开全部贴边便签。 | 以当前贴边机制为主，不新增堆叠、小圆点或独立收起动画；普通隐藏、归档和演示遮蔽保持各自语义。 |
| P1-3 | 演示时快速隐藏 | 从托盘或可配置快捷键隐藏可见便签，结束后恢复；明确提示正在隐藏，意外退出后可找回。 | Ghost Notes 展示了屏幕共享隐私场景。第一步优先做可验证的主动隐藏；录屏排除仅在兼容性验证充分后再决定。 |

## 五、后续扩展功能清单（需先评估）

v1.10.0 已按第四节顺序交付六项优化。实现与测试结果见 [v1.10.0 开发与发布验证](./18-v1.10.0-开发与发布验证.md)；当前后续评估从下表开始。

| 顺序 | 候选 | 适用痛点与最小范围 | 进入开发前必须验证 |
| --- | --- | --- | --- |
| 1 | 用户主动绑定工作场景 | 对单张便签手动关联本地应用窗口或文件；匹配时提示或显示，失配时退回普通便签。默认关闭，可随时解除。 | Windows 窗口标题/路径变化、多个同名窗口、隐私元数据存储、误显示和多屏行为。先不要求浏览器扩展或联网。 |
| 2 | 本地便签互链 | 在正文中显式插入到另一张便签的链接，点击聚焦目标；删除或导出时提示失效链接。 | 富文本与 Markdown 模式的兼容、导出后的链接可读性、回收站恢复后的目标 ID 稳定性。 |
| 3 | 可选相似便签提示 | 仅在用户主动触发时本机比较标题与正文，列出疑似重复项；只提供查看与人工合并，不自动删除。 | 中文文本效果、误判率、加密或锁定数据的处理、性能和解释性。 |
| 4 | 大数据量本地全文索引 | 当真实规模测试表明现有增量缓存不足时，再建立可删除、可重建的本地索引；覆盖标题、正文、清单及附件元数据。 | 明确便签数量和响应时间阈值；断电一致性、中文检索、加密数据残留、磁盘占用及索引损坏回退。索引不能成为读取便签的前提。 |
| 5 | 手动图片文字识别 | 仅对用户选定的本地图片离线识别，并让结果可搜索；识别失败不影响原图。 | 安装包体积、中文识别质量、CPU 占用、临时文件与加密附件的明文残留。当前优先级低于找回原有文本。 |

**暂不纳入：** 强制账号与云端服务、后台持续读取剪贴板、自动上传图片与笔记、未经确认的自动合并、把便签改造成重型块编辑器。它们偏离离线桌面便签的核心体验，且会增加隐私或维护成本。

## 决策与验证顺序

1. 先用本地样本验证 P0 的数据边界：普通便签、主密码保护数据、附件、清单、提醒、归档和回收站；分别覆盖正常、损坏和旧格式数据。
2. 再用实际桌面场景验证 P0/P1 的入口和退出路径：快捷键冲突、多便签、多屏、高 DPI、重启恢复以及纯键盘操作。
3. 每项原型记录“原问题、使用步骤、失败路径、磁盘/内存代价和是否仍可离线使用”；没有明显改善就不进入正式排期。

本轮调研只核对公开的一手资料及仓库当前文档，没有开展用户访谈、长期使用测试或竞品代码审计；痛点与优先级需要在后续真实使用中复核。
