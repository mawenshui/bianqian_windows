# StickyNote P0/P1 六项优化设计方案

**状态：** v1.10.0 已按顺序实施，本文保留原设计与验收依据。**基线：** v1.9.0。**日期：** 2026-10-16。**需求来源：** [现有功能优化与后续扩展清单](../14-现有功能优化与后续扩展清单.md) 的 P0-1～P0-3、P1-1～P1-3。实施差异与验证记录见 [v1.10.0 开发与发布验证](../18-v1.10.0-开发与发布验证.md)。

## 1. 目标、现状与方案选择

本次解决六个连续的使用问题：误改后找回单张便签、把便签完整搬到另一台电脑、用键盘直达旧便签、集中处理分散的清单、管理已有的贴边便签，以及演示时临时遮蔽内容。六项均须在断网时工作，不依赖账号。本文只定义设计与验收条件，不表示已交付。

已核对的代码基线：便签是 `notes/note_{id}.json`，附件和背景图在 `notes/` 下；`core/note.py` 以 500ms 防抖后原子写入。`features/backup.py` 已有带 SHA256 清单的整库 ZIP 与覆盖式恢复；`features/import_export.py` 的 TXT/Markdown 导入导出是可读文本路径，不保证全部字段往返。搜索已有 `LocalNoteRecordCache` 和搜索对话框；清单条目当前只有 `{text, done}`；`core/note.py` 的贴边标签、悬停预览和固定展开已经可用，但贴边状态目前只在运行时维护。现有主密码在 `main.py` 做启动验证；当前便签 JSON 保存流程未调用正文加密，不能把主密码描述为便签文件的磁盘加密。

| 路线 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 直接复用整库备份 ZIP、现有搜索窗和隐藏窗口动作 | 开发量较低 | 备份恢复会覆盖当前库；搜索操作较重；隐藏动作与贴边状态含义不同 | 仅复用校验、读取与窗口接口，不直接复用交互语义。 |
| 在现有模块上增加专用历史存储、迁移包和轻量视图 | 保持原数据格式；能逐项回滚和验证；贴边仍由现有机制负责 | 需要统一保存顺序和状态协调 | **采用。**先落地共同的数据访问边界，再逐项实现。 |
| 改为实时 Markdown 文件库、事件日志及全新工作区系统 | 数据格式更开放，可表达更多布局 | 改动所有保存与窗口流程，迁移风险高 | 本轮不采用。 |

### 共同设计约束

1. 新视图只持有便签 ID 和清单项目 ID，原始便签 JSON 是唯一可编辑数据源。已打开便签先完成待保存写入，再由统一读取层提供快照；禁止窗口、索引和后台导入各自维护相互矛盾的副本。
2. 所有新增 ZIP 输入先做路径白名单、重复项、解压体积、CRC、SHA256、JSON 类型和关联资源校验；校验通过之前不写现有数据。文件写入使用同目录暂存与原子替换，失败保留可定位的安全副本。
3. `归档`、`回收站`、`普通隐藏`、`贴边收起`和`演示遮蔽`是不同状态。演示遮蔽是最高优先级的显示层，不更改便签的基础状态。所有入口均提供键盘操作与明确状态反馈。
4. 搜索缓存和互链索引可从原始 JSON 重建，不进入迁移包的权威数据；全局快捷键走现有冲突检测和用户可配置流程。网络中断不得影响本方案的任何路径。

## 2. P0-1：单张便签本地版本历史

**用户流程：** 便签菜单进入“版本历史”→按时间查看变化摘要和内容差异→选择一版预览→点击“恢复此版本”→系统先保存当前版，再替换选定字段。恢复后的当前版仍可从历史中找回。普通保存无需用户额外操作。

**存储与触发：** 新建 `features/note_history.py`，历史置于用户数据目录 `history/`，按便签 ID 管理快照与内容寻址资源。保存调度先等待该便签之前的 `NoteSaveWorker` 完成，再读取上次成功落盘的版本；只在标题、正文/Markdown、清单、标签、提醒或附件/背景引用的规范化摘要变化时保存旧版。几秒内连续输入合并为一次编辑段，几何、透明度、主题等窗口变化不产生历史。首个新便签不生成空白快照；恢复动作强制记录恢复前版本。每张最多保留 20 版、默认 30 天，另设全局空间上限并显示实际占用；容量不足时先提示历史记录暂停，正常便签保存仍继续。

**资源一致性：** 快照包含便签字段及其当时引用的附件、背景图字节；资源按哈希去重并计数，清理最后一个引用后才删除。恢复时先校验快照资源，再把资源复制到暂存位置，保留当前窗口几何与可见性，仅恢复预览中列明的内容字段；写入失败回滚，不能留下指向不存在附件的 JSON。归档后历史可查看；移入回收站时历史随便签的稳定身份保留，永久删除时才清理；若回收站恢复发生 ID 冲突，历史随新 ID 迁移。整库备份需纳入历史和密钥元数据并通过原有清单验证；P0-2 的便签迁移包默认不携带历史。

**安全边界：** `locked` 当前表示只读，不表示加密。主密码目前只验证启动；历史不得沿用“已有磁盘加密”的错误假设。启用主密码时，历史快照采用独立随机数据密钥和认证加密，数据密钥由主密码派生密钥封装，解锁后仅在进程内存保留；改密码须重新封装，重置主密码须处理或销毁历史。未启用主密码时，历史与当前便签文件一样是本地明文。此设计只保护历史，不声称现有便签 JSON、备份和迁移包已整体加密；发布前必须同步修正用户手册中的相关安全说明。若密钥生命周期或迁移无法可靠实现，本项不能以“历史已加密”名义交付。

**验收：** 连续输入只产生合理数量快照；数日前误改可恢复且恢复前版本可再次找回；附件被删除后旧快照仍能恢复；归档、回收站和 ID 冲突后历史归属正确；断电、损坏快照、磁盘满及主密码变更均不会破坏当前便签。

## 3. P0-2：可往返的本地迁移包

**用户流程：** “导入导出 → 导出可迁移包”展示便签数、附件数、体积、包含内容及明文提示；生成 `.zip`。目标设备选择“导入可迁移包”，先看到校验结果、预期新增数、标签/主题影响及失败项，再确认。首版以空库迁移为完整往返的验收路径；若目标库已有用户便签，只提供取消或先保存安全备份并明确进入单独的合并流程，不静默覆盖。

**包格式：** 与现有整库备份区分，顶层 `manifest.json` 包含 `package_type: "stickynote-transfer"`、`schema_version: 1`、源应用版本、生成时间、文件大小与 SHA256 映射。正文使用原始便签 JSON；携带 `tags.json`、引用到的附件与背景图，以及需要的自定义主题资源。TXT/Markdown 可附作可读副本，不参与无损导入。排除主密码哈希、同步凭据、缓存、日志、机器专属路径、临时窗口状态和历史记录。导出前等待所有待写便签落盘；只使用相对路径，禁止 ZIP 穿越、符号链接与重复成员。

**导入事务：** 独立 `TransferPackageService` 复用备份的校验器与暂存/回滚原则，不调用 `restore_backup_internal()` 覆盖全库。空库导入也要先生成现状安全备份，完整校验后在暂存目录构造目标数据，检查 ID、附件引用和主题映射，再一次性提交；提交失败恢复安全备份。启动时自动生成的空白占位便签可在确认后移除。若某自定义主题无法安全加载，预览必须标明并要求用户选择默认主题，不能声称无损。导入后重建搜索缓存和互链索引，重新加载提醒，窗口坐标按目标屏幕可用区域修正。

**验收：** 在空白便携版上完成“导出→断网复制→导入→逐项核对”，标题、富文本/Markdown、清单、标签颜色、提醒、附件、背景图与归档状态一致；重复文件名、缺失附件、校验不符、超限 ZIP、旧版/未知 schema 都会在写入前给出明确结果。旧的 TXT/Markdown 和整库备份入口保持原语义。

## 4. P0-3：键盘快速切换已有便签

**用户流程：** 托盘“快速切换便签”或可配置的全局快捷键打开小型输入框；输入即显示标题、内容片段、标签与“桌面/已隐藏/已贴边/已归档”状态。上下键选取，Enter 聚焦，Esc 关闭；空查询按最近使用显示少量便签。回收站不参与。

**实现边界：** 从 `features/search.py` 抽出共享的本地记录读取、匹配和排序函数，快速切换只做轻量 UI，不建立第二份索引。已打开便签使用内存中的最新状态；未打开便签用原有 `LocalNoteRecordCache`，缓存损坏时回退原始 JSON。普通隐藏项走 `manager.open_note()`；已贴边项走其现有固定展开路径；已归档项先预览，再由用户明确选择取消归档。不要因为搜索选中就自动改变归档状态。新增快捷键必须在设置中可修改、冲突可见，托盘入口始终可用。

**验收：** 离线环境可用；搜索与原搜索窗在标题/正文命中和归档状态上保持一致；选中后在两次键盘动作内定位并聚焦便签；贴边项不会留下孤立标签，归档项不会被悄悄取消归档；快捷键注册失败仍可从托盘操作。

## 5. P1-1：跨便签清单聚合视图

**用户流程：** 托盘“清单总览”展示未完成、已完成两组，提供来源便签、筛选和“定位便签”；点击复选框立即更新原便签清单。默认排除回收站和已归档便签，归档项可选择只读查看。

**数据设计：** 当前条目只有 `{text, done}`，不能把列表位置当长期身份。新增稳定的 `item_id`；旧数据读取时兼容，首次修改该便签时补齐 UUID 并一次保存。抽出共享清单操作服务，以 `(note_id, item_id)` 定位；已打开便签经 `ChecklistWidget` 的修改和撤销栈写入，未打开便签在读取最新 JSON 后原子修改，通知搜索和总览刷新。重复点击、同时编辑、条目已删除或便签被归档时不盲写，先刷新并告知用户。聚合页不是第二份任务数据库，不保存另一套完成状态。

**验收：** 聚合页勾选与便签内勾选双向即时一致；撤销/重做仍有效；新增、删除、重排条目后不会误勾另一项；归档、回收站、恢复及多个窗口同时操作时无重复或丢失；纯键盘可筛选、勾选和跳转。

## 6. P1-2：以现有贴边收起为主的状态管理

**范围调整：** 保留“拖到屏幕边缘→滑出并留下标签→悬停预览→点击箭头或 Enter 固定展开”作为唯一贴边收起机制。**不做新的便签堆叠、工作区、小圆点或第二套收起动画。**本项只补齐贴边状态的保存、查找和恢复，让已有功能可靠地覆盖多便签、多屏和重启场景。

**交互：** 托盘“贴边便签”按屏幕和边缘列出当前贴边项，可定位标签、固定展开选中项或“展开全部贴边便签”。已手动隐藏、归档、删除的便签不出现在此列表。现有单条标签的悬停/点击、旧版交互开关、错位排列和动画时长保持原规则；批量展开只调用现有恢复流程，不保存另一套窗口位置。

**状态：** 为便签持久化 `edge_collapsed`、`hidden_edge` 与收起前几何；原有 `auto_hidden`、`hide_tab` 继续作为运行时 UI 状态。启动时先读取数据并重建标签，再显示窗口，避免正文短暂闪出；在屏幕拔插或 DPI 改变后用现有可见区域映射和标签避让重新定位。记录缺损或边缘值无效时把便签安全地显示到可见屏幕，并记录可诊断原因。用户固定展开后清除持久化收起标记；仅悬停预览不改变它。布局预设只更新展开几何，不把贴边标签位置当正文窗口位置。

**与 P1-3 的关系：** 演示遮蔽期间标签也被遮蔽，但 `edge_collapsed` 不变；结束后标签按原边缘恢复。“展开全部”只改变当前确实贴边的便签，不改变普通隐藏项。托盘快速切换打开贴边项时复用 `manager.open_note()` 的固定展开语义。

**验收：** 四条边缘、同边多标签、多屏拔插、DPI 切换和重启后，贴边便签仍可从标签或托盘找回；没有重复标签、屏外丢失或展开后再次意外收起；原有悬停预览行为不变。

## 7. P1-3：演示时快速隐藏

**用户流程：** 托盘“开启演示遮蔽”执行一次性全局遮蔽，托盘只显示中性状态和“结束演示遮蔽”入口；可选配置全局快捷键。进入时隐藏普通便签窗口、贴边标签、搜索/清单等内容窗口，托盘通知与提醒弹窗不展示便签正文。结束后按进入前的基础状态恢复；提醒仍记录到期，结束后在提醒中心查看。此功能是主动隐藏，不承诺在任意录屏软件中实现系统级窗口排除。

**状态与失败恢复：** 管理器维护全局 `presentation_active` 和进入前的可见性快照。遮蔽只覆盖显示层，不写入便签的 `archived`、普通隐藏或 `edge_collapsed` 字段；遮蔽期间新建/打开请求须先退出模式或在后台保持不可见。进入状态和恢复快照先原子落盘，再隐藏窗口；若应用异常退出，下次启动先恢复遮蔽状态，绝不先闪出正文，用户从托盘明确结束。恢复时忽略已删除/归档项，普通隐藏仍隐藏，贴边项仍贴边；失败则维持遮蔽并提示可重试。

**验收：** 演示模式下桌面与屏幕截图中没有便签正文、贴边标题标签或内容弹窗；重启后仍遮蔽；结束后各类便签回到进入前状态，提醒未丢失。验证 Windows 屏幕共享和录制的实际画面，但不把主动隐藏表述为录屏排除能力。

## 8. 实施顺序、验证与文档同步

1. **前置基础：** 统一已打开/磁盘便签的读取与保存顺序，补清单稳定 ID 和窗口状态定义；核对并修正主密码与磁盘加密的用户文案。这个阶段不改变现有便签字段含义。
2. **P0-1 → P0-2 → P0-3：** 先把误改恢复和资源快照做稳；再构造可验证、可往返的包；最后共享搜索读取层并加轻量切换窗。每项做完需补自动化测试，先跑受影响测试再跑完整测试集。
3. **P1-1 → P1-2 → P1-3：** 聚合清单复用稳定 ID；贴边状态持久化和托盘管理复用原交互；演示遮蔽最后叠加，按“演示遮蔽 > 基础可见状态”处理冲突。
4. **Windows 实机验证：** 每项覆盖键盘、托盘、休眠/重启、多屏和高 DPI；历史与迁移覆盖断电模拟、磁盘满、损坏 ZIP、附件缺失及主密码变更；演示遮蔽覆盖截图、共享窗口与异常重启。按 [项目维护与发布规范](../../AGENTS.md) 完成测试与发布闭环后才能宣称已实现。

本设计的新增字段采用向后兼容默认值。交付实现中，历史引用资源随每个快照封装，未采用跨快照内容寻址去重；迁移包暂不提供非空库合并；演示遮蔽为主动隐藏，未实现系统级录屏窗口排除。这些边界以 v1.10.0 用户手册和验证文档为准。
